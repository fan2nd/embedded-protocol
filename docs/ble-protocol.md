# BLE 协议修订：统一帧、捎带确认、无会话号

当前为 v6：无包尾，固定开销 17 字节，HELLO 标识 RLB6、能力版本 6，不兼容旧 v5 帧。已完成 115200 baud 的烧录、AT 回读、故障注入恢复和短时同时双向验证；尚未重跑 v6 完整矩阵。测试记录不保留。旧定义见 [v4 归档](archive/ble-protocol-v4.md)。

## 统一帧结构

HELLO、DATA、ACK 使用完全相同的结构，不设独立 ACK 短帧，不包含会话号。所有整数小端。

```text
A5 5A | type:u8 | seq:u32 | ack_next:u32 | length:u16 | payload | CRC32C:u32
```

固定开销 17 字节，length 为载荷字节数，上限 1024。CRC32C 覆盖包头到载荷末尾。只保留二进制包头 A5 5A，中间及 CRC 不转义。AT 命令以 CRLF 结束；手册未给出模块内部 AT 识别边界，因此二进制包头不构成任意载荷绝对防碰撞保证。完整候选帧 CRC 校验失败时，丢弃该候选帧的全部字节，从它的结束位置向后寻找下一包头，不重新扫描坏帧载荷。长度越界或类型非法时尚未形成合法候选帧，逐字节向前找头；长度字段本身损坏但仍在范围内时，可能连带丢弃后续字节，由超时重传恢复。合法但重复或乱序的 DATA 不重复交付、不跨越缺口推进接收位置。

| 类型 | 值 | seq | ack_next | 载荷 |
| --- | --- | --- | --- | --- |
| HELLO | 1 | 0，不占 DATA ID | 本端下一期待接收的 DATA ID | 版本、能力和固定窗口参数 |
| DATA | 2 | 本端新数据的递增 ID | 本端下一期待接收的 DATA ID | 应用数据 |
| ACK | 3 | 0，不占 DATA ID | 本端下一期待接收的 DATA ID | 普通确认及心跳为空 |

收到合法 DATA 或 ACK 后，先处理其中的 ack_next，立即释放已确认数据及窗口额度；再处理 DATA 载荷。DATA 重复或乱序不妨碍其携带的合法确认生效。超出本端已发送范围的确认无效，重复或回退确认不重置超时。HELLO 的确认位置仅用于链路恢复校验，不允许未完成握手的控制包直接释放在途数据。

## 捎带确认与调度

接收位置变化，或收到重复/乱序 DATA 时，标记需要确认。发送前读取最新 ack_next：

1. 如果有当前可以发送的 DATA（新数据或到期重传），将最新 ack_next 放入它的统一头部，不再另发相同位置的 ACK。
2. 如果没有当前可以发送的 DATA，立即发送 ACK。窗口已满、字节额度不足或队列被阻塞，都算没有可发送 DATA；不能为了等待业务数据而拖延确认。
3. ACK 不占 DATA 窗口额度。发送队列保留控制帧空间，避免双方窗口满时无法确认。
4. 已经开始发送的帧不可修改。编码后若又收到新 DATA，新的确认保持待发送状态，不能被旧快照清除。
5. 重传保持原 DATA seq 和应用载荷，但刷新 ack_next，并重新计算 CRC。只取消已确认的 DATA 副本；被取消的副本不能视为已经成功捎带最新确认。
6. 不对 ACK 再发送 ACK。空闲心跳复用 ACK。窗口固定、不慢启动、不缩窗；每个包独立计时，最多 8 次发送。

## 按帧长缩放超时与重传率

最新规则为 `ceil(完整帧字节数 / 128) × 100/200/400 ms`。使用包含包头、载荷、CRC的实际帧长度，不使用 ATT 分片长度、应用载荷长度或整个窗口字节数。第一次提交完成后等待第一档；每次重传提交完成后进入下一档，第三档封顶。确认推进不改变其他包的截止时间。

| 完整帧字节数 | 倍数 | 超时 ms |
| --- | --- | --- |
| 64、128 | 1 | 100 / 200 / 400 |
| 182、256 | 2 | 200 / 400 / 800 |
| 512 | 4 | 400 / 800 / 1600 |
| 1024 | 8 | 800 / 1600 / 3200 |

重传率 = 实际重传 DATA 发送次数 / 实际 DATA 发送总次数。分母含初发与重传，排除未发送的计划包、HELLO、ACK；初次发送次数另列。尚未提交任何字节就取消的重传不计数，部分提交后取消的重传计一次。该口径不会因同一包多次重传而超过 100%，也不同于最终未交付数据比例。

矩阵每格依次给出：下行速率 / 上行速率 / 下行丢包率 / 上行丢包率 / 下行重传率 / 上行重传率。结果仅用于当次反馈，结束后清理。

UART 一次突发仍是一个完整帧，帧间处理接收和确认，不整窗等待。Mac 每个 ATT 分片提交前及写队列等待期间继续处理确认。捎带确认主要用于同时双向有业务数据的场景；单向测试仍需要对端独立发送 ACK。

## 去掉会话号后的重放边界

两方向分别维护递增 DATA ID，重连不清零、不回绕；HELLO 不得把已经交付的接收位置回退。ACK 只确认已发送的连续前缀。ID 用尽后停止发送，不能静默回绕复用。

这能在进度未丢失时拒绝旧 DATA 的重复交付和旧 ACK 的回退。要保留跨重启抗重放，必须为固定对端持久化发送序号及接收交付进度，并定义掉电恢复与首次配对规则；只在 RAM 保存序号的实现不具备这一保证。当前固件没有实现该持久化，不能把删除会话号描述成不影响原有跨重启抗重放能力。CRC 也不提供发送方身份认证。

## 当前测速应用约定

HELLO 请求载荷为 `RLB6 + byte_budget:u32 + tx_floor:u32`，响应为 baud:u32、max_payload:u16、max_packets:u16、version:u16（6）、max_window:u16、byte_budget:u32、tx_next:u32。其公共 ack_next 告知当前接收位置。较旧的 tx_floor 只得到当前位置，不清除计数或回退序号；调用方同步位置后重新请求。允许在已经记录失败的测试轮次之间显式放弃未交付尾部、从新 floor 开始；这个操作属于测试边界，不能冒充上一轮可靠交付成功。

每个方向的 DATA ID 在测试轮次及 BLE 重连间保持递增；MCU 重启后状态丢失。当前仅提供同一次 MCU 运行期间的序号去重，不提供跨重启抗重放。

DATA 载荷首字节 0 为测试数据，后续字节计有效吞吐；首字节 1 为上行启动，后接 count:u32、payload_length:u16、window:u16。START 也占 DATA ID，设备优先以首个上行 DATA 捎带对 START 的确认。整包 N 字节包含 17 字节链路开销和 1 字节测试标识，有效测试数据为 N−18 字节。

独立诊断 crate `ble-bench-payload` 保留 ACK 查询及统计元数据：2 查询快照、3 下行统计、4 上行结束。结束统计中第 4 个 u32 记录设备通过 DATA 携带待发确认的次数。普通空载荷 ACK 不触发 ACK 回复。

`--duplex` 同时双向验证捎带确认；常规矩阵仍先下行再上行，保持历史比较口径。双向小样本成功不能替代完整双向负载矩阵。


随机包长的下限随固定开销变为 17+8=25 字节；有效测试数据为整包长度减 18（17 链路开销、1 测试标识）。历史 v5 使用 27 字节下限，不能与当前定义混用。

当前硬件 doBT-01X 的 AT 事务及配置流程由独立驱动处理；doBT-8AS 使用另一个型号驱动。8AS 手册明确 `AT+CMD=0` 可关闭连接后的普通 AT 识别，但 CMD 查询/设置自身例外，因此不能将它描述为彻底禁用 AT。
